# Enterprise templates and execution workstations

This study covers public product pages, vendor documentation, and open standards. The trading observations describe documented workflows. The layout choices below are design inferences for Utkristi UI.

## Enterprise web patterns

| Reference | Observable pattern | Application in Utkristi UI |
| --- | --- | --- |
| [Linear Enterprise](https://linear.app/enterprise) | A focused opening claim, product diagrams, and a progression from organizational problem to shared workflow. | Pair one headline and a single primary action with a miniature release workspace. Let the preview explain what the product does. |
| [Stripe Enterprise](https://stripe.com/enterprise) | Business-specific pathways, operational proof, and product examples at different levels of detail. | Give the trust strip concrete platform controls and make the capabilities section easy to scan. Use a sample release checklist as proof of the template's workflow. |
| [Vercel Enterprise](https://vercel.com/enterprise) | Capability groups connect infrastructure to governance, security, and operational concerns. A trial form gives readers a clear next step. | Group three capabilities by the people who own them. Keep the demo request form short and keep its completion feedback close to the action. |

The enterprise landing template uses an expressive hero, a denser product preview, a trust strip, and a capability grid. Product illustrations use HTML and kit icons so copy remains selectable and the illustration can reflow at small widths. Signal uses violet and larger radii for product marketing. Ledger uses teal and smaller corners for a more compact operational style. Terminal uses amber and tight corners for data tools.

## Execution workstations

| Workflow | FlexTRADER evidence | Bloomberg evidence | Design inference |
| --- | --- | --- | --- |
| Order triage | FlexTRADER supports configurable workspaces, multi-asset orders, and order-specific execution tools. [Product overview](https://flextrade.com/products/flextrader-execution-management-system/) | EMSX centralizes listed products and broker routing in one workspace. [Equity and listed trading](https://professional.bloomberg.com/products/trading/electronic-markets/listed/) | Keep the blotter visible while inspecting an order. Put symbol, side, size, filled quantity, and status in the first scan path. Use a deliberate selection control with a visible selected state. |
| Routing and fills | FlexTrade documents automated broker and algorithm selection and liquidity indications surfaced in the blotter. [FlexTRADER product overview](https://flextrade.com/products/flextrader-execution-management-system/) · [FlexIOI](https://flextrade.com/resources/flextrader-executes-trade-from-goldman-sachs-using-indication-of-interest-functionality/) | The EMSX API exposes order and route subscriptions separately and delivers fills through route updates. It provides identifiers for orders, routes, and fills plus an API sequence field. [Subscription guide](https://emsx-api-doc.readthedocs.io/en/latest/programmable/emsxSubscription.html) | Model the order as the parent of routes and fills. Keep aggregate quantity in the blotter and drill down to destination, strategy, and fill time and price in the inspector. |
| Execution quality | FlexTrade discusses keeping cost estimates visible across live orders and post-trade analytics. [TCA workflow](https://flextrade.com/resources/measuring-executions-impact-a-modern-approach-to-tca/) | Bloomberg documents order-level performance, benchmark comparisons, IOIs, VWAP, and pre-trade TCA in or alongside EMSX. [Pre- and in-trade analytics](https://professional.bloomberg.com/products/trading/trade-analytics/pre-trade/) | Keep analytics attached to the order context. Define metric units, benchmarks, and timestamps alongside values. Add dense comparisons only where they support a specific decision. |
| Data recovery | FlexTrade describes monitoring order and FIX conditions and surfacing exceptions in context. [TradeGuide](https://flextrade.com/resources/flextrade-introduces-tradeguide/) | EMSX distinguishes initial snapshots, heartbeats, and incremental events. The API documents sequence gaps and different order and route field availability. [Subscription guide](https://emsx-api-doc.readthedocs.io/en/latest/programmable/emsxSubscription.html) · [Programmable API](https://emsx-api-doc.readthedocs.io/en/latest/programmable/index.html) | Show data freshness with an explicit timestamp and text. Preserve the last snapshot during a gap, then reconcile against a fresh snapshot before resuming updates. |

The demo implements searchable, sortable orders, a status filter, route and fill inspection, density control, and a stale snapshot toggle. Orders, prices, destinations, and timestamps are simulated. Each demo order has one route. A production data model needs stable instrument and order keys, a one-to-many route collection, deduplicated fills, explicit state transitions, and reconciliation of partial updates. Broker actions also need authorization, explicit order intent, acknowledgement handling, and an audit trail. Linked views can share instrument context through an adapter such as FDC3 if the deployment uses an interoperable desktop. [FINOS FDC3 API](https://fdc3.finos.org/docs/api/ref/Types)

LSEG separates order and position blotters in REDI and documents parent/child and basket workflows in TORA. Trading Technologies exposes order books, fills, positions, and an audit trail as separate widgets. These reinforce a boundary between order inspection and account-level exposure. An audit panel should distinguish order state transitions, exchange messages, and errors. [LSEG trading workflows](https://www.lseg.com/en/data-analytics/trading-solutions/equities-stock-trading) · [TT widget catalog](https://library.tradingtechnologies.com/trade/overview/tt-platform/description-tt-platform/tt-pro-advanced-features/) · [TT audit trail](https://library.tradingtechnologies.com/trade/order-management/audit-trail/description-audit-trail/audit-trail-overview/)

On desktop, a narrow inspector leaves most space for the blotter. Small containers stack the inspector and keep numeric columns available in a labelled horizontal scroll region. Tabular digits and right alignment make quantities easier to compare. Text identifies side and order status alongside color. [WCAG Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## Theme implementation

| Axis | Responsibility | Current implementation |
| --- | --- | --- |
| Appearance | Surfaces, text, semantic statuses, and system preference | Existing Night, Paper, Glass, and System selectors and React provider |
| Preset | Button fill, accent text, focus indication, and corner scale | Scoped `data-ut-preset` with `signal`, `ledger`, and `terminal` |
| Density | Spacing for repeated data rows | Local `data-density` and a row padding token in the desk stylesheet |
| Accessibility preferences | Motion, transparency, contrast, and platform rendering | Existing kit preferences plus text labels, keyboard controls, and larger row buttons for coarse pointers |

Carbon's distinction between a token's role and its value supports retaining the kit's semantic component tokens. Atlassian describes switching themes over the same token vocabulary. The Design Tokens Community Group resolver models variations as modifiers. Utkristi UI maps the presets to existing hue roles in CSS and keeps density on a separate control. CSS and Tailwind builds consume the same source. [Carbon themes](https://www.carbondesignsystem.com/building-blocks/foundations/themes/overview) · [Atlassian design tokens](https://atlassian.design/foundations/design-tokens) · [DTCG resolver](https://w3c.github.io/cg-reports/design-tokens/CG-FINAL-resolver-20251028/)

The preset sets text and focus from the appearance's stroke role and uses a separate fill/foreground pair for primary buttons. Glass keeps its readable foreground for accent text and uses the preset hue on filled controls. Status tones come from the base appearance, so switching a brand color does not change what warnings and fills mean. Put a preset on the same element as a nested appearance, or on a descendant of that appearance. React portals mirror the nearest appearance and preset attributes so the template's dialog keeps its styling when moved to the document body. Copy the layout CSS from the block's reference to reproduce its layout outside the docs.

Normal text targets 4.5:1 and meaningful control boundaries target 3:1 against adjacent colors. Test button labels in their default and hover states, focus on the actual surface, and statuses on both opaque and Glass surfaces. Density should change row rhythm without changing status semantics or the user's selected order. A virtualized grid would need a known row height and overscan measurement before adopting this template's density controls. [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [WCAG non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) · [AG Grid compactness](https://www.ag-grid.com/react-data-grid/theming-compactness/)

## Framework delivery

Flowbite combines reusable markup and JavaScript with framework-specific libraries and setup guides. Utkristi UI now publishes framework-independent styles and a scoped initializer for native dialogs and keyboard-operated tabs. The Frameworks guide demonstrates the same dialog in HTML, React, Vue, Svelte, and Angular. The complete component API remains available in React. This separates portable markup and behavior from the state and lifecycle APIs each framework owns. [Flowbite JavaScript and framework support](https://flowbite.com/docs/getting-started/javascript/)
